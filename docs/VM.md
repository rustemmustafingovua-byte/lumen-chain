# Lumen VM — смарт-контракты внутри цепи

Контракт исполняется **каждым узлом сети**, а его состояние входит в `state root`.
Значит переписать его нельзя: пришлось бы переписать историю у всех узлов сразу.

## Что умеет

| | |
|---|---|
| Стек | 1024 элемента, значения — 256-битные беззнаковые |
| Память | байтовая, до 1 МиБ, расширяется как в EVM |
| Хранилище | ключ → значение, значения переживают вызовы |
| Газ | лимит на транзакцию (по умолчанию 1 000 000), считается за операцию |
| Журналы | LOG0…LOG4 — темы и данные, попадают в блок |
| Ошибки | REVERT и out-of-gas откатывают изменения хранилища |

## Инструкции

Полный набор — как в EVM, с теми же номерами:

```
00 STOP   01 ADD   02 MUL   03 SUB   04 DIV   05 SDIV  06 MOD
10 LT     11 GT    14 EQ    15 ISZERO 16 AND  17 OR   18 NOT  19 BYTE
30 ADDRESS 33 CALLER 34 CALLVALUE 36 CALLDATASIZE 37 CALLDATALOAD 39 CODESIZE
50 POP  51 MLOAD  52 MSTORE  53 MSTORE8  54 SLOAD  55 SSTORE
56 JUMP  57 JUMPI  58 PC  59 MSIZE  5b JUMPDEST
60-7f PUSH1…PUSH32
80-8f DUP1…DUP16      90-9f SWAP1…SWAP16
a0-a4 LOG0…LOG4
f3 RETURN  fd REVERT  fe INVALID
```

**Порядок операндов — как в EVM:** первым снимается вершина стека, она же левый операнд.
`PUSH1 3 PUSH1 10 SUB` даёт 7 (10 − 3).

## Как задеплоить

Транзакция с `data`:

| data | Что делает |
|---|---|
| `deploy:<hex>` | деплой: код исполняется, если он ничего не возвращает — это и есть исполняемый код; если вернул байты — они становятся исполняемым кодом (как конструктор в EVM) |
| `call:<адрес>:<hex>` | вызов: hex — calldata, изменения хранилища применяются только при успехе |

```bash
# байткод: PUSH1 1, SSTORE в слот 0, STOP
lumen contract deploy 600160005500
lumen contract call 0x…а��рес
lumen contract list
```

## Газ

| Операция | Газ |
|---|---|
| обычная инструкция | 1 |
| PUSH / копирование | 2–3 |
| SSTORE (новый слот) | 20 000 |
| SSTORE (обновление) | 5 000 |
| LOG | 375 + память |
| память (за слово) | 3 |

Бесконечный цикл упрётся в газ и откатится — сеть не встанет.

## Чего нет (и почему)

| Нет | Почему |
|---|---|
| KECCAK256 | используется SHA-256 из `node:crypto` — проще и без нативных зависимостей |
| внешних вызовов между контрактами | добавлю в v0.8 вместе с очередью вызовов и лимитом глубины |
| `CALLVALUE` перевода на контракт | есть, но перевод пока не зачисляется на баланс контракта при вызове |
| precompile и верификация Solidity | компилятор Solidity не подключён: пока байткод пишется вручную или ассемблером |

## Ассемблер для тестов

```ts
import { assemble } from "lumen-chain"
const code = assemble("PUSH1_0 SLOAD PUSH1_1 ADD PUSH1_0 SSTORE STOP")
```
