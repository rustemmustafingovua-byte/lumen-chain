# Модель угроз

## Что защищено

| Атака | Защита |
|---|---|
| Подделка транзакции | ed25519-подпись + проверка в реестре |
| Повтор транзакции | строгий nonce, ожидаемый `account.nonce` |
| Двойная трата | списание до начисления, nonce запрещает повтор |
| Подделка блока | подпись продюсера, Merkle-корень, prevHash, высота |
| Форк цепи | 2/3-финальность по весу stake |
| Фронт-раннинг | детерминированный продюсер по весу, таймлок-слотов |
| Инфляция сверх плана | фиксированный supply + 3% годовых, начисление только за блоки |
| Манипуляция AMM | комиссия 0.3%, постоянное произведение, slippage-параметр в keeper |
| Кража ключа в keeper | ключ в `~/.lumen/keeper.json` (600), никогда в репозитории |

## Известные ограничения (v0.1)

| Ограничение | Статус |
|---|---|
| Нет защиты от eclipse-атаки (узел изолирован от сети) | gossip без адресации; для защиты нужен seed-узел с проверкой подписей |
| Нет ограничения на размер gossip-пакета | блок ограничен MAX_BLOCK_TXS, но пакет блоков — нет |
| Нет смарт-контрактов в цепи | v0.2 |
| `LumenAMM.withdraw` не различает доли LP | **известный риск**: документирован, будет исправлено в v0.2 вместе с долями |
| Ключи хранятся в открытом виде на диске | улучшение: keystore или TEE в v0.3 |
| Нет защиты от гонки в keeper | keeper работает с одним nonce-менеджером; в v0.2 — nonce-очередь |
| Keeper тратит ключ казны | ограничено политикой (порог, лимит за сделку, лимит за сутки, запас 2% против проскальзывания) и журналом; ключ можно вынести в отдельный адрес |
| Цена пула манипулируется | лимит проскальзывания в политике; keeper не покупает, если цена хуже заданной |
| P2P: нет аутентификации соседей | сообщения подписываются только продюсером блока; сам канал не аутентифицирован |

## Правила для контрибьюторов

1. Никогда не добавляйте секреты в репозиторий.
2. Любое изменение консенсуса — с тестом и объяснением в PR.
3. Изменения в `core/crypto.ts` и `core/ledger.ts` требуют ревью двух человеков.
4. Баг-бounty выплачивается только за воспроизводимый сценарий.
